# HIRA 급여기준·KCD 코드체계 실무

건강보험 급여기준·질병분류 코드체계 도메인은 `hira_updates_search`, `openapi_hira_disease_check_code`, `openapi_hira_get_drug_price`, `kcd_get_name`, `kcd_search_codes` 5개 MCP tool이 담당한다. 이 문서는 각 tool이 실제로 다룰 것으로 추정되는 국내 제도의 실무 구조를 웹 조사로 확인하고, 대회 예상 질문에 대한 tool 호출 전략을 정리한다.

## 1. HIRA 급여기준 고시 체계

- 급여기준의 근거는 보건복지부 고시 「요양급여의 적용기준 및 방법에 관한 세부사항」이며, **행위**와 **약제**를 별도 고시로 분리 관리한다(예: 행위 고시 제2026-51호, 약제 고시 제2025-73호 — 두 번호는 검색 시점 기준이며 개정 시마다 갱신됨, 정확한 최신 번호는 매 호출 시 재확인 필요).
- 고시 본문 아래 "세부인정기준"이 있어 상병별·약제별로 투여 대상, 용법·용량, 투여 기간, 병용 제한 등을 표 형태로 명시한다. HIRA는 이를 정기적으로 e-book(PDF)으로도 배포한다(예:「암환자에게 처방·투여하는 약제에 대한 요양급여의 적용기준 및 방법에 관한 세부사항」 2025.12판).
- **산정특례**는 중증질환자의 본인부담률을 낮추는 별도 제도로, 국민건강보험법 제44조·시행령 제19조 및 「본인일부부담금 산정특례에 관한 기준」(행정규칙)에 근거한다. 등록 시 청구 상병코드에 "특정기호"(예: 희귀질환 V800=등록일로부터 5년 적용, V810=연 60일 한도, 결핵 A15~A19는 2년, 상세불명 희귀질환은 1년)가 부여되며, 이 특정기호가 급여 청구 시 KCD 상병코드와 함께 심사 근거로 쓰인다.
- **암질환심의위원회**는 항암제·항암요법의 급여 인정 여부를 심의하는 HIRA 산하 위원회다. 신청 접수일로부터 60일 이내 심의를 거쳐 사용 승인 여부와 인정 범위를 요양기관에 통보한다. 심의 결과와 별개로 "진료심사평가위원회 심의사례"가 정기적으로(월 단위) 공개되며, 대한병원협회 등 유관 기관 게시판에도 재배포된다 — 실무에서는 "암종별 항암요법 인정여부" 같은 항목으로 개별 사례가 공개되고, 요양기관은 유사 사례를 인용해 사전심사·이의신청 근거로 활용한다.

## 2. 상병코드(주상병) 심사 시 성별·연령·감염병 제한

HIRA는 통계청 KCD를 기반으로 청구용 "상병마스터"를 별도 관리하며, 여기에 청구 심사에 필요한 부가정보를 얹는다.

| 부가정보 | 의미 | 예시 |
|---|---|---|
| 주상병 사용 구분 | N=주상병 불가코드 (질병코딩 원칙상 주상병으로 청구 불가) | B95~B98(세균·바이러스 등 기타 감염체) — 2024년 개정 시 약 4,987개 코드가 신규 지정 |
| 성별 구분 | X=여성 전용, Y=남성 전용 | 남성 전용 11개(예: Q98, Klinefelter 증후군 등 Y염색체 이상), 여성 전용 74개(예: F84.2 레트증후군 — 여성에 압도적으로 발현하는 X-연관 질환) |
| 법정감염병 구분 | 표제어 상병에 한해 감염병 예방법상 분류 표기 | 코로나19 등 신종 감염병 코드 신설·명칭변경 시 상병마스터에 즉시 반영 |
| 상한/하한 연령 | 해당 상병코드로 청구 가능한 연령 범위 | 소아·신생아 특이 상병, 노인성 질환 등 |

- 원리: 성별·연령이 맞지 않는 상병코드로 청구하면 "착오기재"로 간주되어 심사 단계에서 반려(심사불능) 처리된다. HIRA는 개정 시 통상 3개월의 안내(유예) 기간을 두고, 이후부터 본격적으로 심사불능 처리를 적용한다.
- 여성 생식기 악성/양성 신생물(C51~C58, D25~D28), 여성 골반 질환군(N70~N81), 산과적 상병(A34 산과적 파상풍 등)이 대표적인 성별 제한 예시로 자주 언급된다. 다만 이는 산부인과 영역의 직관적 예시이고, F84.2(레트증후군)처럼 비생식기 질환도 유전적 특성상 성별 제한이 걸리는 경우가 있다는 점이 실무적으로 덜 알려진 함정이다.
- 주상병 불가코드는 "성별/연령 제한"과는 다른 축의 제한이므로 혼동 주의: 전자는 코딩 원칙(불완전코드·분류상 위치) 문제, 후자는 환자 속성(성별/연령) 문제다. `openapi_hira_disease_check_code`는 이 두 축을 모두 반환하는 것으로 tool 설명에 명시되어 있다.

## 3. HIRA 약가 데이터 — 상한금액·급여 등재/삭제

- **상한금액**: 건강보험이 해당 약제에 대해 지급을 인정하는 최고 가격으로, 「약제 급여 목록 및 급여 상한금액표」 고시에 등재된다. 제네릭은 최초 등재 신약(오리지널) 가격의 일정 비율로 산정되며, 이후 실거래가·약가 재평가 등에 따라 조정된다.
- **주성분별 가중평균가격**: 동일 주성분·동일제형·동일함량 제품이 여러 회사에서 다른 상한금액으로 등재된 경우, (상한금액×청구량)의 합을 청구량의 합으로 나눈 가중평균가격을 별도 산출해 참조 지표로 쓴다. → 실무 함정 ①: **동일 성분이라도 제품(품목)마다 상한금액이 다를 수 있다.** 성분명만으로 조회하면 여러 상한금액이 나올 수 있으므로, 정확한 급여 판단에는 품목기준코드(제품코드) 단위 조회가 필요하다.
- **급여 등재/삭제**: 약제는 등재일부터 급여 대상이며, 급여목록에서 삭제된 이후에는 원칙적으로 비급여 전환되거나 처방 자체가 제한된다. 다만 삭제 고시에도 유예 규정이 붙는 경우가 있다(예: 별지 고시에서 특정 삭제 약제를 특정 시점까지 한시적으로 요양급여 대상으로 인정). → 실무 함정 ②: **"삭제됨" 판정만 보고 끝내면 안 되고, 삭제일자와 함께 유예/경과조치 여부를 확인해야 한다.** 또한 삭제일이 지난 약제를 과거 시점 처방 기록 기준으로 재조회하면 "당시에는 급여였다"는 결과가 나와야 하므로, 조회 기준일(적용일) 파라미터를 명시하지 않으면 오판할 수 있다.
- `openapi_hira_get_drug_price`는 tool 설명상 "급여 등재 상태, 약가 code, 상한가"와 "삭제 및 적용일 정보"를 함께 반환하므로, 위 두 함정(제품별 상한가 차이, 삭제/적용일 미확인)을 코드 레벨에서 방지하도록 결과의 제품코드·적용일 필드를 반드시 함께 확인해야 한다.

## 4. KCD-8 vs KCD-9

| 구분 | KCD-8 (8차) | KCD-9 (9차) |
|---|---|---|
| 고시일 | 2020-07-01 | 2025-07-01 |
| 시행일 | 2021-01-01 | 2026-01-01 |
| 주요 개정 | ICD-10 기준 갱신 반영 | 신규 세분코드 67개 추가, 저빈도 세분코드 91개 삭제·정비(코로나19 분류 간소화, 우울증 치료저항성 세분화 등), 소분류 2,084 / 세분류 12,506 / 세세분류 6,113개 |
| 코드 구조 | 알파벳 1자리 + 숫자 2자리(대분류~소분류, 예 A00~Z99) + 소수점 이하 세분류·세세분류 숫자(예 A00.0) — ICD-10 계열 구조 준수 | 동일 구조 계승, WHO 국제표준(ICD-10/ICD-11) 반영 강화로 단일코드 조회 구조 일부 개선 |

- **현재(2026-08 기준) 표준**: KCD-9가 2026-01-01부로 시행되어 공식 표준이 된 상태다. `kcd_get_name`/`kcd_search_codes`의 기본값이 KCD-9로 설정된 것은 이 시행일과 일치한다. 다만 청구 시스템·통계 집계 쪽에서는 전환 유예기간 동안 KCD-8 코드가 병행 조회될 가능성이 있어, 오래된 청구 데이터나 구버전 문서를 다룰 때는 KCD-8 버전 지정 조회가 필요할 수 있다(정확한 병행 운영 기간은 출처 미확인, 추가 검증 필요).
- 코드 자릿수 세부 규칙(소수점 이하 몇 자리까지 실사용되는지, 알파벳 대역별 예외 등)은 KOICD 공식 코딩지침서 원문을 직접 확인하지 못해 상세 구조까지는 확정하지 못함 — **정확한 출처 미확인, 추가 검증 필요**.

## 5. 암질환 off-label 요법의 "인정 비급여" 승인

- 원칙: 항암제는 식약처(MFDS) 허가사항 범위 내 사용이 원칙이며, 허가 범위 내에서도 HIRA가 공고한 세부인정기준을 벗어나면 약값 전액을 환자가 부담(비급여)한다.
- 허가사항을 초과(off-label)하여 사용하려는 경우, 요양기관 내부 다학제적위원회(또는 공용 다학제적위원회) 심의를 먼저 거친 뒤 "허가초과 항암요법 신청(신고)" 서식을 작성해 HIRA에 신고해야 사용할 수 있다.
- 신규 항암요법의 급여화 또는 인정 범위 확대는 암질환심의위원회 심의를 거치며, 접수일로부터 60일 이내 승인 여부·인정 범위가 통보된다. 심의를 통과해 "인정"된 off-label 요법은 급여 또는 인정 비급여로 분류되어 이후 유사 환자 청구의 선례(심의사례)로 축적된다.
- `hira_updates_search`가 다루는 `hira_cancer_drug_regimen` 소스는 바로 이 "암질환심의위원회가 인정한 항암요법 레지멘(약제 조합·용법·적응증)" 데이터베이스로 추정된다(공식 tool 스키마상 상세 필드는 확인하지 못함, 추가 검증 필요). `hira_cancer_drug_notice`는 이 심의 결과가 반영된 개별 공고문/notice를, `hira_biz_infobank`는 더 넓은 범위의 급여기준 일반 고시를 커버하는 것으로 추정된다.

## 6. 대회 도구 매핑 — tool 호출 전략

대회에서 나올 법한 전형적 질문: **"이 환자가 이 진단으로 이 약을 처방받을 때 보험 적용이 되는가?"**

| 단계 | 사용 tool | 목적 | 이번 조사와의 연결 |
|---|---|---|---|
| 1 | `kcd_search_codes` | 자연어 진단명 → KCD 코드 후보 변환(KCD-9 기본, 필요 시 KCD-8 병행) | §4 KCD-8/9 버전 이슈 — 최신 표준은 KCD-9(2026-01-01 시행)이지만 구버전 문서/과거 청구 데이터는 KCD-8일 수 있으므로 version 파라미터를 명시적으로 다뤄야 함 |
| 2 | `openapi_hira_disease_check_code` | 확정된 KCD 코드가 청구에 유효한지, 주상병 사용 가능 여부, 환자의 성별·연령과 상병코드 제한이 충돌하지 않는지 확인 | §2 성별/연령/감염병 제한·주상병 불가코드 — 여기서 걸리면 이후 단계(약가·급여기준 조회)가 무의미해지므로 반드시 2단계에서 조기 검증 |
| 3 | `openapi_hira_get_drug_price` | 처방 약제의 급여 등재 상태·상한금액·삭제/적용일 조회 | §3 함정 두 가지 — 성분명이 아닌 제품(품목)코드 단위로 확인, 조회 기준일(처방일)을 명시해 삭제일 경과 여부 판단 |
| 4 | `hira_updates_search` | 진단×약제 조합에 대한 세부인정기준·암질환심의위원회 공고·인정 off-label regimen 검색 — 급여 인정의 "조건"(용법·용량·투여기간·병용제한 등)을 최종 확인 | §1, §5 — 특히 암 영역에서는 일반 급여기준만으로 부족하고 `hira_cancer_drug_notice`/`hira_cancer_drug_regimen` 소스까지 검색해야 off-label 인정 여부까지 답할 수 있음 |

- 순서가 중요한 이유: 1→2에서 진단 자체가 무효/제한 대상이면, 3→4에서 아무리 약가·급여기준이 맞아도 최종 답은 "청구 불가"가 되어야 한다. 반대로 2까지 통과했더라도 3에서 해당 약제가 이미 급여목록에서 삭제된 상태라면(경과조치 유무 확인 필요), 4의 세부인정기준을 조회하는 것 자체가 무의미할 수 있다.
- 암 환자 케이스에서는 4단계에서 일반 급여기준(`hira_biz_infobank`)뿐 아니라 암질환 특화 소스(`hira_cancer_drug_notice`, `hira_cancer_drug_regimen`)를 함께 질의해, "허가사항 범위 내 급여"인지 "허가초과지만 인정된 off-label regimen"인지를 구분해서 L2 프롬프트에 명시적으로 전달해야 답변의 정확도가 올라간다.
- 산정특례 대상 여부(특정기호)는 이번 5개 tool만으로는 직접 조회되지 않는 것으로 보인다 — `openapi_hira_disease_check_code` 응답에 특정기호 필드가 포함되는지는 실제 호출 전까지 확정할 수 없으므로, 대회 중 첫 호출 결과에서 필드를 직접 확인 필요(추가 검증 필요).

## 전략적 시사점

- 이 도메인의 질문은 대부분 **"진단 코드 유효성 → 약가/급여 상태 → 세부인정기준"의 3단 검증 체인**이며, 어느 한 단계에서 실패하면 뒤 단계 결과를 무시하고 "불가" 답변으로 조기 종료하는 로직이 hallucination을 줄이는 데 중요하다. [06. 근거정합성_hallucination](06_근거정합성_hallucination.md)의 원칙과 결합해, 각 단계 tool 응답을 인용 없이 다음 단계로 넘기지 않는 체이닝 검증기를 하네스에 넣을 만하다.
- KCD-9가 2026-01-01부로 이미 시행된 현재 표준이라는 사실은 대회 시점(2026년 하반기) 기준으로 중요한 최신 정보다 — L2 프롬프트나 few-shot 예시를 짤 때 "최신 KCD는 8차"라고 가정하면 시대에 뒤떨어진 답변이 나올 위험이 있다.
- 약가 조회는 성분명이 아닌 제품(품목) 단위로 상한금액이 갈리는 경우가 흔하므로, `openapi_hira_get_drug_price` 호출 전에 가능하면 제품명/품목코드까지 좁혀서 질의하고, 여러 후보가 나오면 그 사실 자체를 답변에 명시하는 것이 안전하다.
- 암질환 off-label 영역은 일반 급여기준 고시만으로는 커버되지 않고 별도의 심의 프로세스(다학제적위원회 → 암질환심의위원회, 60일 이내 통보)를 거친 선례성 데이터이므로, `hira_updates_search`가 이 세 소스(hira_biz_infobank/hira_cancer_drug_notice/hira_cancer_drug_regimen)를 구분 없이 한 번에 검색하는지 여부를 대회 초반에 실제 호출로 확인해 두는 것이 좋다.
- KCD 코드의 정확한 자릿수 규칙과 상병마스터의 전체 부가정보 스키마는 이번 웹 조사로 완전히 확인하지 못했다 — 대회 중 `kcd_get_name`/`openapi_hira_disease_check_code`를 실제로 몇 개 코드에 대해 호출해보고 반환 필드를 직접 관찰하는 것이 문서보다 빠르고 정확한 검증 방법이다.

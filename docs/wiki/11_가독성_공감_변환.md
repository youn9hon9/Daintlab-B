# 가독성 · 공감 · 일반인 눈높이 조율 (FM 출력 → 대국민 언어 변환)

`docs/Claude-chat-log/논문 및 유스케이스.md`에서 발굴, 기존 리서치에는 없던 카테고리. 의과학 FM/PubMed 원문은 전문가용 언어이므로, "대국민 건강관리 챗봇"이라는 이 대회의 타겟 자체가 요구하는 별도의 변환 레이어 문제.

## 핵심 사례
- **RephQA** (2026, Yale): 공중보건 질의응답에서 LLM 응답의 가독성이 환자 교육에 필수적임에도 그동안 충분히 다뤄지지 않았다는 문제의식에서 출발한 벤치마크. 일반인 대상 건강 챗봇 평가에서 **가독성을 별도 축**으로 다루는 방법론을 참고할 수 있음.
- **The Biased Oracle** (2025): LLM은 환자의 교육 수준에 따라 텍스트 복잡도를 조정하는 능력을 보였지만, 여전히 권장 가독성 수준을 초과하는 지나치게 복잡한 의학 설명을 만들어내는 경향이 있음. **의과학 FM 원출력을 그대로 쓰면 안 되고 별도 변환 레이어가 필요**하다는 점을 뒷받침하는 실증 자료.
- **Mayo Clinic 공감 연구** (Luo et al., 2024): 실제 환자 메시지·의사 답변 데이터셋에서 LLM이 생성한 대안 답변을 비교한 결과, LLM 기반 챗봇이 **공감적 소통에서 인간 의사를 능가할 잠재력**을 보임. 정확성뿐 아니라 공감 표현에서도 승부를 볼 수 있다는 근거.

## 전략적 시사점
- PubMed 원문이나 법령 조문을 검색해오더라도, 최종 답변 생성 단계에서 "일반 국민이 이해할 수 있는 언어로 재작성"하는 명시적 변환 스텝(요약/lay-language rewriting)을 파이프라인에 넣는 것이 필요 — 단순히 검색 결과를 인용구로 붙이는 방식은 가독성 면에서 감점 요인이 될 수 있음
- Biased Oracle의 발견(교육 수준별 복잡도 조정은 되지만 여전히 과도하게 복잡함)을 감안하면, 단순히 "쉽게 써줘"라는 프롬프트만으로는 부족할 수 있음 — 답변 생성 후 가독성 점검(예: 문장 길이, 전문용어 비율 체크) 단계를 별도로 두는 것이 더 안정적
- 공감 표현은 정확성과 별개의 축으로 채점될 가능성이 높으므로([07번 문서](07_블라인드_평가_사례.md)의 Med-PaLM 2 9개 평가축 참고), 톤 설계(첫 문장에서 환자의 우려를 인정하는 표현 등)를 의도적으로 시스템 프롬프트에 반영할 가치가 있음
- 이 축은 [10. 안전성/캘리브레이션](10_안전성_캘리브레이션.md)과 상충할 수 있음에 주의 — 지나치게 공감적/안심시키는 톤이 MedPRESS류 "환자가 안심을 구하며 압박하는" 시나리오에서 안전 조언을 흔드는 방향으로 작용하지 않도록 균형 필요

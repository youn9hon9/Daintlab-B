# 멀티턴 환자 시뮬레이션 평가 프레임워크

해커톤의 심사 방식(고정 시작질문 → 시뮬레이션 환자 에이전트가 후속발화 생성 → 최대 3턴 → 임상의 블라인드 비교)과 구조적으로 가장 유사한 연구군. **이 폴더에서 가장 우선적으로 정독할 가치가 있는 자료.**

## 핵심 논문
- **AgentClinic** (arXiv 2405.07960): 의사 에이전트가 시뮬레이션 환자 에이전트·측정 에이전트와 상호작용하며 불완전한 정보 하에서 최대 20턴까지 대화 후 진단을 내리는 멀티모달 벤치마크. 9개 전문분야·7개 언어 평가. AgentClinic-MedQA(대화형)와 AgentClinic-NEJM(멀티모달) 두 축으로 구성.
  - **중요 발견**: 정적 문제(MedQA)를 순차적 대화 형식으로 바꾸면 진단 정확도가 원래의 1/10 이하로 급락 — 즉 "정보를 아는 것"과 "대화로 끌어내는 것"은 전혀 다른 능력. 이 대회의 3턴 구조에서도 동일한 함정이 예상됨.
  - Claude 3.5 계열이 다른 백본 대비 대화형 설정에서 상대적으로 우수했다는 결과 — 대화 유도(문진) 능력이 벤치마크 정확도와 별개 축임을 시사.
- **AutoMedic** (Automated Evaluation Framework for Clinical Conversational Agents, arXiv 2512.10195): 의료 데이터셋에 기반해 대화형 에이전트를 자동 평가하는 프레임워크 — CoEval과 유사한 목적의 최신 시도로, 평가 축 설계에 참고할 만함.
- **MedDialogRubrics** (arXiv 2601.03023): 멀티턴 임상 상담을 평가하는 루브릭 기반 벤치마크 — "무엇을 기준으로 좋은 멀티턴 의료 대화라 판단하는가"에 대한 세부 채점 기준을 제공, CoEval/블라인드 심사 기준을 유추하는 데 가장 직접적으로 도움될 자료.
- **SycoEval-EM** (Sycophancy Evaluation in Simulated Clinical Encounters for Emergency Care, arXiv 2601.16529): 응급 상황에서 LLM이 환자에게 아첨(맞춰주기)하는 경향을 평가 — 환자가 원하는 답(예: "괜찮다고 해줘")에 영합하지 않고 레드플래그를 놓치지 않는지가 평가축이 될 수 있음을 시사.
- **T²-GRPO** (Turn-Trajectory Group Relative Policy Optimization for Caregiver Agents, arXiv 2606.08875): 멀티턴 궤적 전체를 강화학습 보상으로 최적화하는 기법 — 파인튜닝까지 시도한다면 참고할 수 있는 방법론(대회 규정상 파인튜닝 허용 여부 확인 필요).
- **OpenHospital** (arXiv 2603.14771): LLM 기반 집단 지성을 진화시키고 벤치마킹하는 아레나형 환경 — 여러 에이전트 협업 구조 참고용.
- **ThreadMed-QA** (2026): 실제 r/AskDocs 스레드에서 최대 9턴짜리 환자-의사 대화 2,437개를 추출한 벤치마크. GPT-5조차 완전 정답률 41.2%에 그쳤고, 테스트한 5개 모델 모두 턴0→턴2로 갈수록 성능이 유의미하게 저하됨을 확인 — **프론티어 모델도 턴이 진행될수록 무너진다는 실증 데이터**로, "멀티턴에서 버티는 설계"가 이 대회의 실질적 차별화 포인트가 될 수 있음을 뒷받침.

## 전략적 시사점
- **턴1 설계가 결정적**: AgentClinic의 "대화형으로 바뀌면 정확도 폭락" 결과는, 이 대회에서도 정보 부족 상태에서 섣불리 확정적 답을 주는 것이 위험함을 뒷받침. 문진(되묻기) 전략이 필요하다는 이전 분석과 일치.
- **Sycophancy 방지**: 시뮬레이션 환자 에이전트가 특정 방향으로 몰아가는 후속 질문을 해도, 안전하지 않은 방향으로 맞춰주지 않도록 하는 가드레일이 채점에 영향을 줄 수 있음.
- **CoEval 실전 활용**: CoEval은 이미 `github.com/lunit-io/CoEval`에 공개되어 있음(검증됨, [01번 문서](01_루닛_의과학FM.md) 참고). MedDialogRubrics·AutoMedic의 루브릭 구조는 CoEval의 LLM-as-judge 메트릭(HealthBench 루브릭 등)이 멀티턴 대화 품질을 어떤 세부 기준으로 판단할지 해석하는 보조 자료로 함께 활용.

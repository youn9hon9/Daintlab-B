# 자체 멀티턴 테스트 하네스 구축 (CoEval의 사각지대 보완)

[01번 문서](01_루닛_의과학FM.md)의 CoEval 심층 조사에서 확인한 사각지대 — CoEval 16개 데이터셋 중 실시간 시뮬레이션 환자 에이전트가 다음 발화를 생성하는 방식은 없음 — 를 메우기 위해, 대회의 실제 루닛 하네스가 공개되기 전 **우리가 직접 재현 가능한 오픈소스 도구**를 조사.

## 재사용 가능한 오픈소스 코드

### AgentClinic (검증 완료, WebFetch로 README 직접 확인)
- 저장소: https://github.com/SamuelSchmidgall/AgentClinic
- 의사·환자 에이전트가 각각 `--doctor_llm`, `--patient_llm` 파라미터로 지정되는 구조 — **우리 챗봇을 `doctor_llm` 자리에 그대로 끼워넣을 수 있음**
- 턴 수는 `--total_inferences`로 제어 (기본 20턴, 이 대회는 3턴으로 낮춰서 재현 가능)
- 커스텀 HuggingFace 모델은 `HF_{hf_path}` 형식으로, 커스텀 API 엔드포인트는 OpenAI 호환 방식으로 연결 가능해 보임
- 환자 에이전트는 인지 편향(최근성, 빈도, 허위 합의, 자가진단, 인구통계 편향 등)을 시뮬레이션하도록 설계되어 있어, 루닛의 시뮬레이션 환자 에이전트가 어떤 종류의 "비이상적 환자 반응"을 만들어낼지 감을 잡는 데 유용
- **실행 예시**:
  ```bash
  python3 agentclinic.py --openai_api_key "KEY" --doctor_llm gpt4o --patient_llm gpt4o --inf_type llm
  python3 agentclinic.py --openai_api_key "KEY" --doctor_llm "HF_mistralai/Mixtral-8x7B-v0.1" --inf_type llm
  ```

### HealthBench 독립 구현 (m42-health, 검증 완료)
- 저장소: https://github.com/m42-health/healthbench — OpenAI 원본 HealthBench의 독립형 구현
- **3단계 파이프라인**: (1) vLLM으로 OpenAI 호환 서버 구동 → (2) `generation.py`로 응답 생성 → (3) `judge.py`로 의사 작성 루브릭 기준 채점
  ```bash
  python -m vllm.entrypoints.openai.api_server --model <우리모델> --port 8000
  python generation.py --model_id="our-chatbot-v1"
  python judge.py
  ```
- CoEval도 OpenAI 호환 엔드포인트를 요구하므로([01번](01_루닛_의과학FM.md) 참고), **이 파이프라인 구조가 CoEval 인터페이스와 그대로 호환** — 하나의 엔드포인트 구현으로 CoEval과 HealthBench 독립 구현 양쪽에서 자체 평가 가능
- HealthBench 규모: 5,000개 다국어 멀티턴 대화, 262명 의사(60개국, 26개 전문분야)가 작성한 48,562개 루브릭 기준, 대화당 평균 11.4개 기준, 긍정/부정 점수(-10~10)를 조합해 최종 점수 산출, 모델 기반 채점기는 의사 판단과 대조 검증됨

### PatientSim (2025, 페르소나 기반 환자 시뮬레이터)
- MIMIC-ED/MIMIC-IV 임상 프로필에 기반, 성격·언어능력·병력 회상 수준·인지 혼란 수준 4개 축으로 총 37개 페르소나 조합 생성
- 오픈소스, 커스터마이즈 가능. 최고 성능 오픈소스 백본은 Llama 3.3 70B
- PhysioNet에도 공개: https://physionet.org/content/persona-patientsim/1.0.0/
- **AgentClinic보다 페르소나 다양성이 세밀함** — "순진한 환자" "불안해하는 환자" "정보를 잘 안 주는 환자" 등 다양한 유형을 테스트하고 싶다면 AgentClinic보다 이쪽이 적합

### MedAgentSim (MICCAI 2025)
- 저장소: https://github.com/MAXNORM8650/MedAgentSim
- "Self-Evolving Multi-Agent Simulations for Realistic Clinical Interactions" — 에이전트가 상호작용을 거치며 스스로 진화하는 구조. 여러 라운드에 걸친 자가개선 루프를 참고할 만함

### 기타 참고
- **Awesome-Agentic-Clinical-Dialogue** (xqz614): 임상 대화 에이전트 관련 자료 모음 저장소 — 추가 도구 탐색용
- **AutoRedTeamer** (2025): 의료 LLM을 위한 자율 red-teaming, lifelong attack integration — [10번 문서](10_안전성_캘리브레이션.md)의 MedPRESS류 압박 시나리오를 자동 생성하는 데 참고 가능
- **MultiChallenge** (arXiv 2501.17399): 프론티어 LLM에게도 어려운 멀티턴 대화 평가 벤치마크 — 일반적인(의료 외) 멀티턴 능력의 기준선 참고용

## 전략적 시사점 — 실행 계획
1. **엔드포인트 표준화가 먼저**: CoEval도, m42-health/healthbench도, AgentClinic의 커스텀 모델 연결도 전부 OpenAI 호환 엔드포인트를 전제로 함. 우리 RAG+멀티에이전트 파이프라인을 대회 시작 즉시 OpenAI 호환 API로 감싸두면 이 모든 도구를 그대로 재사용 가능
2. **AgentClinic을 3턴으로 축소해 자체 시뮬레이션 루프 구축**: `--total_inferences`를 3으로 낮추고 `--doctor_llm`에 우리 엔드포인트를 연결하면, 루닛의 실제 하네스가 공개되기 전이라도 "시뮬레이션 환자가 후속 질문을 만들고 우리가 답하는" 구조를 미리 연습해볼 수 있음
3. **PatientSim의 페르소나 축**(불안/정보차단/인지혼란 등)을 자체 테스트 시나리오 설계에 차용하면, MedPRESS류 "환자가 안심을 구하며 압박하는" 상황이나 "정보를 잘 안 주는 환자" 같은 까다로운 케이스를 미리 커버 가능
4. **HealthBench 루브릭 작성 관행**(대화당 11.4개 기준, 긍정 69.3%/부정 30.7% 비율)을 참고해, 자체 벤치마크 문제에도 유사한 루브릭을 미리 만들어두면 채점 기준 설계 감각을 익힐 수 있음
5. 다만 이 모든 건 어디까지나 **대체재**이지 루닛의 실제 하네스와 동일하지 않음 — 대회 시작 후 실제 하네스 스펙이 나오면 이 자체 하네스를 실제 스펙에 맞게 즉시 조정할 것

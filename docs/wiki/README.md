# 모델 개선 지식 위키

이 위키는 단순 자료 보관소가 아니라 다음 후보를 설계하는 에이전트의 작업 메모리다.
공식 계약 원문은 [competition](../competition/README.md), 후보별 수치는
[evaluations](../evaluations/README.md)을 사용한다.

## 에이전트 권장 읽기 경로

### 새 후보를 설계할 때

1. [평가 인덱스](../evaluations/README.md)에서 현재 기준선과 약점을 확인한다.
2. [모델 개선 플레이북](21_에이전트_모델개선_플레이북.md)에서 실험 단위를 정한다.
3. 지연 문제라면 [입력 예산 전략](22_입력예산_지연최적화_전략.md)을 읽는다.
4. 검색·인용 변경이라면 [런타임과 MCP 관측](20_런타임_아키텍처와_MCP_관측.md)과
   관련 도메인 문서를 읽는다.
5. 구현 후 candidate 문서에 가설·SHA·결과·판정을 남긴다.

## 현재 핵심 교훈

- Y2는 품질과 16/16 완주를 함께 달성한 기준선이다.
- U2와 Y3에서 “문맥을 더 고려하라”는 지시를 늘렸지만 instruction following이
  하락했다. 규칙 추가는 문맥 이해의 대체물이 아니다.
- Y2/Y3의 retrieval은 21개 tool schema를 한꺼번에 읽고 65초를 소진하는 패턴이
  반복됐다. 다음 개선은 timeout 축소보다 입력 범위 축소가 우선이다.
- 검색 결과와 citation evidence는 다른 데이터 흐름이다. navigation 결과가 아니라
  실제 `cite_uid`가 있는 원문만 최종 근거로 사용한다.
- 로컬 점수는 리더보드보다 낙관적일 수 있으므로 성공률·지연·축 점수를 함께 본다.

## 지식 갱신 규칙

- 후보 한 번의 결과는 `evaluations`에만 기록한다.
- 두 후보 이상에서 반복된 패턴만 wiki의 일반 원칙으로 승격한다.
- 사실, 관측, 가설을 문장 안에서 구분한다.
- benchmark 원문과 rubric을 복제하거나 hidden evaluation을 역설계하지 않는다.

# B004 로컬 평가 대기

## 핵심 가설

B003의 D5 시간 예산과 모델 의미 로직을 유지하면서 cold-start 연결만 직렬화하고 정상
upstream 동시성을 6에서 4로 낮추면, 시작 경쟁과 순간 부하로 인한 502를 줄이면서
coverage-v2의 처리량을 유지할 수 있다.

## 버전 식별자

- 트랙: 벤치마크상
- 버전: `B004`
- 브랜치: `yh-submission`
- SHA: 커밋 후 확정
- 리더보드 제출: 수행하지 않음
- 평가 상태: 현장 단독 평가 대기

## 변경 범위

| 항목 | B003 | B004 |
|---|---:|---:|
| 요청 제한 | 90초 | 90초 |
| upstream 제한 | 30초 | 30초 |
| retrieval 제한 | 40초 | 40초 |
| 정상 L2 동시성 | 6 | **4** |
| cold-start guard | 제거 | **복원** |

prompt, retrieval, citation, MCP 예산과 D5 시간 제한은 바꾸지 않는다. cold-start guard는
첫 HTTP 응답을 받을 때까지만 연결 생성을 직렬화하며, 이후에는 동시성 4가 적용된다.

## 근거

- B003 첫 실행은 컨테이너가 종료되며 32/32가 즉시 실패했다.
- B003 재실행도 HTTP 502 12건과 `run_timeout` 1건으로 19/32만 성공했다.
- F003은 cold-start guard를 유지했지만 동시성 6에서 20건의 502를 기록했다.
- 두 결과는 동시성 6의 순간 부하와 B003의 guard 제거를 함께 경고한다.

## 예상 개선과 위험

- 예상 개선: cold start 재현성 회복, 502 감소, 동시성 2보다 짧은 queue wait.
- 예상 위험: 동시성 4도 upstream 수용량을 넘거나 30초 attempt 제한이 짧아 실패할 수 있다.
- 해석 제한: guard 복원은 B003의 결함 교정이므로 순수 동시성 실험의 전제 조건이다.

## 현장 평가 기준

다른 후보와 동시에 실행하지 않고 `.\proxy yh-submission`으로 평가한다. 32/32 완주,
inference·judge·run timeout 0건, `promotion_eligible=true`일 때만 승격을 검토한다. 420초는
실제 Trial 제한이 아니라 엄격한 사전 선별 gate로 해석하며, 실패하면 HTTP status와
queue·attempt telemetry를 함께 확인한다.

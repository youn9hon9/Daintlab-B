# B005 로컬 평가 대기

## 핵심 가설

B004의 모델 의미 로직, cold-start 보호와 upstream 동시성 4를 고정하고 요청 시간 창만
120초/50초로 복원하면, 420초 안의 처리량을 유지하면서 30초 upstream 제한에서 발생한
HTTP 502를 줄일 수 있다.

## 버전 식별자

- 트랙: 벤치마크상
- 버전: `B005`
- 브랜치: `yh-submission`
- SHA: 커밋 후 확정
- 리더보드 제출: 수행하지 않음
- 평가 상태: 현장 단독 평가 대기

## 변경 범위

| 항목 | B004 | B005 |
|---|---:|---:|
| 전체 요청 제한 | 90초 | **120초** |
| upstream attempt 제한 | 30초 | **50초** |
| 최종 생성 예약 | 35초 | **50초** |
| retrieval 제한 | 40초 | 40초 |
| upstream 동시성 | 4 | 4 |
| cold-start guard | 유지 | 유지 |

prompt, retrieval round·MCP call, context·evidence 예산, citation 처리와 telemetry는
변경하지 않는다. 세 시간 상수는 initial/retrieval/final 호출이 공유하는 하나의 요청
deadline 정책이므로 함께 조정한다.

## 근거

- B004는 357.92초 안에 32개가 모두 종료됐지만 HTTP 502 7건으로 25/32만 성공했다.
- B004에는 62.08초의 wall-clock 여유가 있어 timeout을 다소 복원할 공간이 있었다.
- F004는 cold-start guard·동시성 4와 50초 upstream 제한에서 31/32, 282.69초를 기록했다.
- B002의 upstream 제한은 75초이므로, B005의 50초 근거는 B002가 아니라 F004의 관측이다.

## 예상 개선과 위험

- 예상 개선: 30초를 초과하는 정상 upstream 응답 회수, HTTP 502 감소, completeness 회복.
- 예상 위험: 느린 요청이 slot을 오래 점유해 queue wait와 전체 실행 시간이 늘 수 있다.
- 구조적 위험: B/F에서 반복 실패한 complex-response 경로는 50초로도 해결되지 않을 수 있다.

## 현장 평가 기준

다른 후보와 동시에 실행하지 않고 `.\proxy yh-submission`으로 평가한다. 32/32 완주,
inference·judge·run timeout 0건, `promotion_eligible=true`일 때만 승격을 검토한다.
420초를 넘기거나 502가 남으면 점수와 관계없이 승격하지 않으며 phase·queue·attempt
telemetry로 다음 가설을 정한다.

# B007 로컬 평가 대기

## 핵심 가설

B006에서 실행당 15~19건의 Retrieval이 모두 약 40초를 소진하고 `no_evidence`로
끝났으므로, runtime과 Generation prompt를 고정한 채 Retrieval을 완전히 끄면 근거
성공률을 잃지 않으면서 420초 안에 32/32를 완주할 수 있다.

## 버전 식별자

- 트랙: 벤치마크상
- 버전: `B007`
- 브랜치: `yh-submission`
- SHA: 커밋 후 확정
- 리더보드 제출: 수행하지 않음
- 평가 상태: 현장 단독 평가 대기

## 변경 범위

| 항목 | B006 | B007 |
|---|---:|---:|
| 전체 요청 / upstream | 120초 / 50초 | 동일 |
| upstream 동시성 | 5 | 5 |
| final 우선 slot | 1 | 1 |
| Generation prompt | 유지 | 유지 |
| Retrieval tool 노출 | 조건부 호출 가능 | **OFF** |
| MCP·evidence 처리 | 유지 | 미진입 |

Generation의 첫 L2 호출에 `retrieve_relevant_content` 도구를 제공하지 않는다. 모델이
도구가 없는 상태에서 tool call을 반환하면 protocol error로 처리한다. Retrieval 코드와
예산은 삭제하지 않아 다음 paired ablation에서 현재 gate 또는 tool shortlist를 다시
시험할 수 있게 유지한다.

## 근거

- B006 두 실행은 모두 30/32, 420초로 실패했다.
- initial·retrieval·final queue wait는 사실상 0ms여서 동시성 병목 가설이 반증됐다.
- Retrieval은 실행별 15~19건 모두 `no_evidence`였고 대부분 40초 제한을 전부 썼다.
- F006은 direct 29건 중심 구조로 로컬 32/32와 실제 Trial 45.88점을 기록했다.

## 예상 개선과 위험

- 예상 개선: 요청당 불필요한 40초 Retrieval과 final 추가 호출 제거, 32/32 완주,
  처리량과 deadline headroom 증가.
- 예상 위험: 최신 수치·법령·허가·급여처럼 외부 근거가 필수인 질문의 accuracy와
  completeness가 하락할 수 있다.
- 해석 경계: B006에서 성공 evidence가 0건이었으므로 이번 실험은 검색 품질 개선이
  아니라 Retrieval 비용의 순효과를 측정하는 ablation이다.

## 현장 평가 기준

다른 후보와 동시에 실행하지 않고 `.\proxy yh-submission`으로 평가한다. 32/32 완주와
`promotion_eligible=true`를 우선 확인하고 B006 대비 accuracy·completeness 및 global
health·health data 점수를 함께 비교한다. 두 번 연속 32/32여도 근거 필수 영역이 크게
회귀하면 Trial 후보로 승격하지 않는다.

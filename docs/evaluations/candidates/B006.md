# B006 벤치마크 후보 평가 피드백

## 판정

**폐기한다.** B006은 B005의 upstream 동시성을 4에서 5로 높이면 마지막 문항의
queue 적체를 해소할 수 있다는 가설이었다. 같은 SHA를 두 번 평가했지만 모두
30/32에서 420초 전체 제한을 소진했다. 점수는 50.01점과 52.18점으로 올랐으나
두 실행 모두 `promotion_eligible=false`다.

telemetry에서는 initial·retrieval·final L2 queue wait가 사실상 0ms였다. 반면
실행마다 15~19건이 RAG 경로에 들어갔고 관측된 Retrieval은 전부 약 40초를 소진한
뒤 `no_evidence`로 끝났다. 따라서 B005의 미완주 원인을 내부 concurrency queue로
본 가설은 틀렸다. 실제 병목은 높은 RAG 진입률과 Retrieval timeout 누적이다.

## 버전 식별자

- 트랙: 벤치마크상
- 버전: `B006`
- 브랜치: `origin/yh-submission`
- SHA: `c54c6bd3f7bb88155fb32d98666c3e0e7ddb2d9d`
- 커밋: `perf(benchmark/B006): 동시성 5로 처리량 안전선 탐색`
- 구조화 결과: [B006.json](../results/B006.json) — 2차 실행
- 실제 Trial: 수행하지 않음

## 변경과 평가 조건

| 항목 | B005 | B006 |
|---|---:|---:|
| 전체 요청 / upstream | 120초 / 50초 | 동일 |
| Retrieval / final 예약 | 40초 / 50초 | 동일 |
| upstream 동시성 | 4 | **5** |
| final 우선 slot | 1 | 1 |

두 실행 모두 coverage-v2 32문항, seed 0, generation concurrency 4, judge
concurrency 8, request/run timeout 120/420초의 동일 조건이다.

## 반복 결과

| 지표 | 1차 | 2차 |
|---|---:|---:|
| 점수 | 50.01 | **52.18** |
| 95% 신뢰구간 | 40.47–59.65 | 42.96–60.72 |
| 성공 | 30/32 | 30/32 |
| inference 실패 | 1 | 0 |
| run timeout | 1 | 2 |
| 전체 시간 | 420.13초 | 420.03초 |
| 평균 모델 지연 | 46.33초 | 52.91초 |
| p95 모델 지연 | 87.57초 | 91.95초 |
| 성공 처리량 | 4.28건/분 | 4.29건/분 |

동시성 증가에도 처리량이 사실상 변하지 않았다. 2차 점수 상승은 동일 문항에 대한
모델·judge 변동 범위이며 런타임 개선으로 해석하지 않는다.

| telemetry | 1차 | 2차 |
|---|---:|---:|
| direct route | 13 | 15 |
| RAG route | 17 | 15 |
| Retrieval 완료 기록 | 19 | 15 |
| Retrieval timeout | **19** | **15** |
| Retrieval 상태 | 전부 `no_evidence` | 전부 `no_evidence` |

RAG에 들어간 요청이 대부분 40초를 쓰고도 evidence를 반환하지 못한 뒤 final 생성을
추가로 수행했다. B006의 문제는 L2 슬롯 수가 아니라 불필요하거나 비효율적인
Retrieval 경로다.

## B007 권고

1. 동시성을 더 올리거나 timeout을 늘리지 않는다.
2. `Retrieval OFF / 현재 gate / 도메인별 tool shortlist`를 같은 manifest로
   paired ablation한다.
3. 일반 의료·공감·응급 안내는 direct로 고정하고, 최신 수치·법령·허가·급여처럼
   외부 근거가 필수인 질문만 RAG에 넣는다.
4. Retrieval에 모든 MCP schema를 주지 말고 질문 도메인별 최소 tool만 제공한다.
5. prompt의 MCP 최대 4회와 코드 상한 2회의 불일치를 바로잡는다.
6. Retrieval 성공 근거가 없는 후보는 점수와 무관하게 검색 개선으로 주장하지 않는다.
7. 32문항 2회 연속 완주 전에는 Trial 후보로 승격하지 않는다.

B006은 동시성 5가 위험해서 실패한 것이 아니라 **RAG 1건당 40초를 반복 소비하는
구조에서는 동시성만으로 전체 처리량을 회복할 수 없다**는 반증이다.

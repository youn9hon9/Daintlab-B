# B001 벤치마크 후보 평가 피드백

## 판정

**승격하지 않는다.** B001은 16/16 완주와 평균 지연 단축에는 성공했지만, 로컬
프록시 점수가 기준 후보 Y2보다 19.90점 낮다. 특히 communication quality,
instruction following, context awareness가 크게 하락해 벤치마크상 후보의 품질
기준을 충족하지 못했다.

법령 질의의 tool schema 축소라는 단일 최적화 가설도 이번 결과만으로는 검증할 수
없다. 평가 결과에는 어떤 표본이 `law` family로 분류됐는지와 schema 감소량이 남지
않았고, 전체 긴 꼬리 지연도 유지됐다.

## 가설과 변경

B001은 Y3의 규칙 기반 `response_guidance`를 제거하고, 명확한 법령 질의에서만
Retrieval L2에 제공하는 MCP 도구를 다음 세 개로 축소했다.

- `openapi_law_search`
- `openapi_law_list_articles`
- `openapi_law_get_article`

법령 도구가 없거나 query가 고신뢰 법령 패턴에 해당하지 않으면 전체 도구로
fallback한다. timeout, retrieval round, citation repair와 evidence budget은 유지했다.

의도는 응답 품질과 완주율을 유지하면서 법령 RAG의 tool schema 입력과 긴 꼬리
지연만 줄이는 것이었다.

## 가설 검증의 한계

코드에는 `family`, 선택 tool 수, schema 문자 수를 로그로 남기는 계측이 있지만 현재
프록시는 후보 컨테이너 로그를 결과 artifact에 수집하지 않는다. 따라서 다음 질문에
답할 수 없다.

1. 16개 중 몇 개가 `law` family로 분류됐는가?
2. 실제 schema 문자가 얼마나 감소했는가?
3. 해당 표본의 retrieval 지연이 대조군보다 줄었는가?
4. 필요한 도구가 숨겨지는 false negative가 있었는가?

이번 점수만으로는 tool filter의 효과와 응답 계보 변경의 효과가 섞여 있다. 다음
후보에서는 행동 변경보다 먼저 관측 가능성을 확보해야 한다.

## B002 권고

1. 추정으로 복원한 Y2가 아니라 실제 검증된 Y2 모델 동작을 대조군으로 고정한다.
2. 대조군에는 코드 경로를 바꾸지 않는 계측만 먼저 추가한다.
3. 후보 컨테이너의 `family`, tool 수, schema 문자 수와 retrieval 지연을 결과 artifact에
   합쳐 문항별로 비교할 수 있게 한다.
4. tool filter를 다시 시험한다면 동일 대조군에 그 변경 하나만 적용한다.
5. communication quality, instruction following과 context awareness가 Y2에서 5점
   이상 하락하면 즉시 폐기한다.
6. 평균 지연뿐 아니라 60초·90초 초과 건수를 승격 기준에 포함한다.

B001의 filtering 구현은 바로 확장하지 않는다. 먼저 정확한 Y2 대조군과 paired
telemetry를 마련한 뒤 재검증한다.

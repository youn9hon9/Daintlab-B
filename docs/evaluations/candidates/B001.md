# B001 설계 기록 — 평가 대기

## 버전과 단일 가설

B001은 벤치마크상 트랙의 첫 후보이다. Y3의 `response_guidance`를 폐기해 가장 좋은
공개 기준선인 Y2의 응답 동작으로 돌아가고, Retrieval L2 입력만 제한적으로 줄인다.

> 고신뢰 법령 질의에 한해 MCP tool schema를 21개 전체에서 법령 도구군으로 줄이면,
> Y2 수준의 품질과 완주율을 유지하면서 RAG 긴 꼬리 지연을 낮출 수 있다.

- 담당 브랜치: `yh-submission`
- 기준선: Y2 54.68점, 16/16 성공, 평균 모델 지연 52.35초
- 폐기 근거: Y3 44.30점 및 동일 모델 재측정 38.86점
- 평가 상태: 현장 랩탑 CoEval·HealthBench 대기

## 변경 범위

법률·법령·조문·의료법·약사법처럼 정보원 종류가 명확한 query에서는
`openapi_law_search`, `openapi_law_list_articles`, `openapi_law_get_article`만
Retrieval L2에 제공한다. 일반 의료·가이드라인·복합 질문에는 전체 MCP 도구를
제공한다. 예상한 법령 도구가 서버에 없으면 전체 도구로 자동 fallback한다.

선택 family, 제공 tool 수, schema 문자 수와 전체 tool 수를 원문 없이 로그로 남긴다.
timeout, retrieval round, citation repair와 evidence budget은 Y2 값을 유지한다.

## 실패 사례 반영

- Y3의 guidance payload와 prompt 규칙은 instruction following·communication을 크게
  떨어뜨렸으므로 제거한다.
- Y2/Y3의 RAG 요청은 80~108초까지 걸렸고 21개 tool schema가 반복 입력됐다.
- timeout을 단축해 실패를 빠르게 만들지 않고 입력 선택 복잡도만 줄인다.
- 애매한 query를 강제 분류하지 않아 필요한 도구를 숨기는 false negative를 피한다.

## 의도적으로 하지 않은 것

- 여러 tool family 동시 분류
- retrieval 진입 keyword gate
- timeout·context·evidence budget 축소
- citation repair 제거
- 제출 API 또는 디렉터리 구조 변경

## 승격 기준

1. 동일 representative 16개 manifest에서 16/16 성공한다.
2. Y2 54.68점에서 3점 넘게 하락하지 않는다.
3. 법령 표본의 schema 문자 수와 retrieval 지연이 감소한다.
4. 법령 citation 성공률이 하락하지 않는다.
5. 전체 fallback 표본의 동작과 품질이 Y2 수준을 유지한다.

실패하면 filtering 동작을 폐기하고 계측 결과만 다음 후보의 근거로 보존한다.

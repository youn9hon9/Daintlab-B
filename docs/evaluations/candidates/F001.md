# F001 프론티어 후보 평가 피드백

## 판정

**승격 보류.** F001은 16개 문항을 모두 완주했고 평균 모델 지연을 19.12초까지 줄였지만,
로컬 프록시 점수는 42.88로 품질 기준선 Y2보다 11.80점 낮았다. 증거 역할 태깅의 목표였던
context awareness는 오히려 26.10점 하락했고 completeness 향상은 1.04점에 그쳤다.

이번 결과만으로는 속도 향상을 증거 역할 태깅의 효과라고 볼 수 없다. F001의 부모 브랜치에는
이미 Y4 계열의 라우팅·timeout 최적화가 포함되어 있기 때문이다. 역할 태깅이 실제로 얼마나
발동했는지도 현재 결과 artifact만으로는 확인할 수 없다. 빠른 실행 기반은 보존하되, 역할 태깅은
계측과 대조군 평가를 거친 뒤 다시 판단한다.

## 변경 가설

F001은 검색 증거에 `primary`, `corroborating`, `caveat` 역할을 부여하고, 검색·생성 프롬프트가
그 역할을 활용하도록 변경했다. 여러 출처의 관계를 명시하면 답변의 완전성, 맥락 인식과 인용
일관성이 좋아질 것이라는 가설이다.

다만 이 후보는 깨끗한 Y2 기준선에서 갈라진 단일 변경 실험이 아니다. 기존 브랜치의 Y4 런타임
최적화와 Y3의 `response_guidance` 계열 동작을 함께 물려받았다. 따라서 점수와 속도의 원인을
역할 태깅 하나로 귀속하면 안 된다.

## 현재 평가가 답하지 못한 질문

결과 JSON에는 최종 점수와 지연은 있지만 다음 정보가 없다.

1. 요청별 `primary`·`corroborating`·`caveat` 할당 개수
2. 실제로 둘 이상의 출처를 결합한 문항 수
3. `no_evidence`, `partial`, 알 수 없는 인용 제거와 인용 누락 경고 횟수
4. direct/RAG 경로와 검색 단계별 지연
5. 역할 태깅이 없는 동일 부모 SHA 대조군 결과

따라서 “역할 태깅이 발동했지만 실패했는지”와 “대부분 primary로만 분류되어 사실상 no-op이었는지”를
구분할 수 없다. 인용 일관성 향상 여부도 현재 judge 축만으로 직접 검증되지 않는다.

## F002 권고

1. F001의 부모 모델을 같은 manifest로 평가해 역할 태깅만 제외한 paired control을 만든다.
2. 요청별 역할 개수, 다중 출처 여부, evidence 상태와 인용 repair 횟수를 구조화 telemetry로 남긴다.
3. 다중 출처 종합과 상충 증거 처리를 직접 요구하는 작은 표적 평가 세트를 추가한다.
4. 역할이 대부분 `primary`라면 분류를 보정하고, `caveat` 사용이 맥락 점수 하락과 연관되면 생성
   프롬프트를 단순화한다.
5. context awareness, instruction following, communication quality 중 하나라도 Y2보다 5점 이상
   하락하면 승격하지 않는 회귀 기준을 둔다.
6. 빠른 런타임 기반과 증거 역할 전략을 별도 변경으로 분리해 각각 검증한다.

F001의 가장 가치 있는 성과는 역할 태깅의 품질 개선이 아니라 **빠르고 안정적인 실행 기반을 확인한 것**이다.
다음 버전은 이 기반을 유지하면서, 관측 가능한 단일 가설 실험으로 전환해야 한다.

# F001 개발 피드백 — 평가 대기

## 트랙과 기준선

`F` 접두사는 `yh-submission2`(프론티어상 트랙)의 새 버전 컨벤션이다. 이전까지 이
브랜치는 `D`/`U`/`Y` 접두사를 `yh-submission`(벤치마크상 트랙)과 공유했고, 그
혼용이 실제로 평가 실행명과 브랜치 SHA가 어긋나는 사고로 이어졌다
([Y4 피드백](Y4.md) 참고). F001은 그 사고 이후 도입된
[컨벤션](../CONVENTION.md)에 따라 이 브랜치에서 기록하는 첫 버전이다.

로컬에서 비교 가능한 가장 최근 기준선은 `Y2`(대표 16개, 54.68점, 16/16
성공, 평균 모델 지연 52.35초)다. F001은 Y2 이후 이 브랜치에 누적된 코드
위에서 시작한다. 즉 Y4의 `should_offer_retrieval` keyword gate와 timeout
축소는 코드에 남아 있고, Y5가 계획했던 "Y3 response_guidance 폐기"와
"법령 tool-family filtering"은 문서로만 기록됐을 뿐 코드에는 반영되지
않았다(`src/guidance.py`, `src/retrieval.py` 확인). F001은 이 두 가지를
되돌리거나 구현하지 않는다. 그 항목들은 지연 최적화 계열의 별도 실험이며,
이번 버전의 변수와 섞으면 원인 분리가 불가능해진다.

## 연구 가설

`yh-submission`(벤치마크 트랙)이 tool schema 축소와 timeout 조정으로 지연을
줄이는 동안, 프론티어 트랙은 개선 우선순위 5–6번인 completeness/context
awareness와 citation 정합성 쪽에서 아직 시도되지 않은 축을 다룬다.

현재 `finalize_retrieval`(`src/tooling.py`)은 evidence item마다 `cite_uid`와
`relevance_score`만 요구한다. Retrieval L2가 여러 출처를 선택해도 최종
Generation은 evidence를 순서 없는 목록으로만 받는다. 서로 다른 출처가 같은
결론을 뒷받침하는지, 아니면 한 출처가 다른 출처의 예외·제한·관할 차이를
나타내는지는 Generation이 evidence 원문에서 스스로 다시 추론해야 한다.
[retrieval.md 규칙 12](../../../prompts/retrieval.md)가 "국가·기준·시행일이
다른 근거를 병합해 하나의 결론으로 요약하지 않는다"고 이미 지시하지만, 그
구분을 구조화된 신호가 아니라 자유 텍스트 안에서 Generation이 다시 찾아내야
한다는 한계가 있다.

> **가설**: Retrieval L2가 `finalize_retrieval`에서 evidence item마다
> `role`(`primary`/`corroborating`/`caveat`)을 명시적으로 태깅하고, Generation이
> 이 role을 근거 합성에 명시적으로 반영하면(핵심 결론은 `primary`로 세우고,
> `corroborating`은 짧게 보강, `caveat`은 예외·제한으로 분리 제시), 다중 출처
> 질문에서 completeness와 context awareness가 개선되고 caveat 근거의 누락·혼입으로
> 인한 근거 정합성 문제가 줄어든다.

이는 tool schema나 timeout을 바꾸지 않는 순수한 근거 합성(evidence synthesis)
전략 변경이며, latency 최적화 축과 독립적으로 ablation할 수 있다.

## 변경 범위

단일 행동 변경: evidence에 argumentative role을 태깅하고 그 role을 최종 답변
합성에 사용한다.

- `src/schemas.py`: `CitableItem`과 `ResolvedEvidence`에 `role` 필드 추가
  (`Literal["primary", "corroborating", "caveat"]`, 기본값 `primary`).
- `src/tooling.py`: `FINALIZE_TOOL` JSON schema의 item 속성에 `role`(enum,
  선택 필드)을 추가해 Retrieval L2가 이 값을 반환할 수 있게 한다.
  `cite_uid`/`relevance_score`는 여전히 필수이므로 role을 생략해도 기존
  동작과 동일하게 `primary`로 처리된다.
- `src/evidence.py`: `EvidenceRegistry.resolve`가 선택된 item의 `role`을
  `ResolvedEvidence`로 그대로 전달한다. 선택 순서, 문자 budget, item 개수
  제한(`max_selected_evidence`, 여전히 2)은 바꾸지 않는다.
- `prompts/retrieval.md`: role 태깅 기준을 설명하는 규칙 13 추가. 관계가
  실제로 확인되지 않으면 억지로 `corroborating`/`caveat`을 만들지 않고
  `primary`로 두도록 명시했다.
- `prompts/generation.md`: role별 합성 방법을 설명하는 규칙 17 추가.
  evidence가 하나뿐이면 기존 규칙 8만 적용되고 이 구분은 개입하지 않는다.

## 의도적으로 하지 않은 것

- `max_selected_evidence`, `max_evidence_chars` 등 evidence budget 숫자 변경
- Y4/Y5가 다루는 tool schema 범위 축소, timeout 조정, keyword gate 수정
- Y3 response_guidance 되돌리기 (Y5의 계획이며 별도 버전에서 다룬다)
- evidence 선택 순서나 개수 제한 알고리즘 변경 — role 태깅과 절대 개수를
  같은 버전에서 섞으면 개선 원인을 분리할 수 없다
- role 미태깅 시 fallback 로직 추가 — 스키마 기본값(`primary`)으로 충분하다

## 예상 실패 조건

- Retrieval L2가 role enum을 신뢰할 수 있게 채우지 못하고 대부분 `primary`로만
  채우면, 구조적 신호가 사실상 no-op이 되어 개선이 관측되지 않는다.
- role 태깅이 finalize_retrieval payload 검증 실패율을 늘리면(예: enum 밖의
  값을 반환) retrieval `no_evidence`/`partial` 비율이 늘어날 수 있다.
- Generation이 `caveat` evidence를 과도하게 강조해 답변이 장황해지거나
  instruction following(형식·범위 준수)이 하락할 수 있다.
- 단일 출처 질문이 대다수인 표본에서는 role 구분이 드물게만 발생해 대표
  16개 표본으로는 효과가 통계적으로 드러나지 않을 수 있다.

## 승격 기준

1. 대표 16개 manifest에서 16/16 성공.
2. Y2 54.68점에서 명백한 하락이 없다(반복 전까지 2~3점 차이는 동률로 취급).
3. instruction following과 accuracy에 큰 회귀가 없다.
4. 다중 출처가 개입된 표본(법령+가이드라인, 국가별 허가 비교 등)에서
   completeness 또는 context awareness가 Y2 대비 개선되거나 최소한 하락하지
   않는다.
5. citation 관련 경고(`unknown_citations_removed`, `citation_missing`) 빈도가
   Y2 대비 늘지 않는다.

유효하면 다음 버전에서 role 정보를 evidence 선택 순서(다양성 있는 소스
우선)에도 반영하는 실험을 별도로 진행한다. 실패하면 role 태깅을 폐기하고,
retrieval L2가 실제로 role을 얼마나 정확히 채웠는지만 계측 결과로 남긴다.

## 평가 상태

현장 실행 대기. 로컬에서는 unit 테스트(`tests/test_evidence.py`,
`tests/test_retrieval.py`에 role 관련 테스트 추가)와 API 계약 테스트
(`tests/test_api.py`), Docker cold-start 스모크(`/v1/models` 200,
`LUNIT_FM_API_KEY` 미설정 시 `/v1/chat/completions` 503으로 정상 실패)만
확인했다. representative 16 scored proxy는 이 문서 갱신 이후
`.\proxy yh-submission2`로 별도 실행한다.

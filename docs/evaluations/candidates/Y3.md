## 원인 해석

Y3는 `clarification_needed`, `missing_context`, `global_context_needed`와 설명문을
모든 generation 요청에 추가한다. 여기에 system prompt 규칙 네 개가 더해졌다.
규칙의 개별 취지는 합리적이지만 다음 부작용이 관측됐다.

1. 모델이 최신 사용자 요청보다 확인 질문과 일반 안전 안내를 우선할 수 있다.
2. regex가 포착한 누락 가능성이 실제 대화의 의미적 충분성과 일치하지 않을 수 있다.
3. 여러 준수 목표가 동시에 주어져 답변이 길어지고 핵심 형식 요구를 놓칠 수 있다.
4. context-aware 지시를 늘렸지만 context awareness가 오히려 하락했다. U2에서도
   유사한 회귀가 있었으므로 반복 가능한 실패 패턴으로 본다.
5. Y3는 입력 최적화 후보가 아니다. guidance payload와 prompt 규칙이 추가돼
   initial/final 입력은 Y2보다 조금 커졌다.

## Retrieval 관측

평가 중 direct 요청은 대체로 12~38초였다. Retrieval 요청은 MCP tool schema
21개를 모두 L2에 전달했고, 반복적으로 65초 retrieval budget을 소진한 뒤
`no_evidence`로 final generation을 수행했다. 대표 RAG 요청의 전체 지연은
약 80~108초였다.

따라서 다음 성능 개선은 전체 timeout을 더 줄이는 것이 아니라 Retrieval L2가 읽는
tool schema와 누적 message를 줄여야 한다.

## 판정

**승격 보류. 기준 후보는 Y2를 유지한다.**

Y3의 guidance 전체를 다음 후보의 기반으로 사용하지 않는다. emergency referral과
health data 개선 사례는 표본 단위로 분석하되, 다음 후보는 Y2에서 출발해 입력 예산
최적화 하나만 검증한다.

후속 전략은 [입력 예산·지연 최적화](../../wiki/22_입력예산_지연최적화_전략.md)를
따른다.

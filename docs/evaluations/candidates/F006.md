# F006 프론티어 후보 평가 및 실제 Trial 피드백

## 판정

**새 공식 기준선으로 승격한다.** F006은 로컬 1차에서 31/32, 2차에서 32/32를
기록해 자체 기준인 동일 SHA 2회 연속 완주에는 미달했다. 그러나 제출 SHA의 실제
Trial이 정상 완료되어 **45.88점**을 기록했다. 기존 공식 기준선 D5의 42.48점보다
3.40점 높으므로 실제 관측을 우선해 F006을 현재 공식 best로 지정한다.

다만 이번 코드 변경은 답변을 바꾸지 않는 관측 기능이다. Trial 점수 상승을 citation
grounding 검사 덕분이라고 해석하면 안 된다. 로컬 RAG 5건은 모두 Retrieval timeout
후 `no_evidence` fallback이었고 citation grounding 이벤트도 0건이었다. 공식 성공은
F005 계열의 direct 응답 품질과 동시성 4 runtime이 실제 환경에서도 완주 가능했음을
입증한 결과다.

## 변경 가설

F006은 F005의 prompt, 라우팅, timeout, 동시성과 evidence budget을 그대로 유지했다.
행동 변경 없이 다음 관측만 추가했다.

1. citation이 붙은 문장과 실제 evidence의 문자 3-gram 포함률 기록
2. Retrieval timeout이 진행 중 MCP 호출을 취소할 때 `mcp_tool_cancelled` 기록

grounding 결과로 답변을 삭제하거나 재작성하지 않으므로 F005와 F006의 점수 차이는
이 기능의 품질 효과가 아니다.

Retrieval L2 단계에서 먼저 시간을 소진했을 가능성과 함께 해석해야 한다.

## F007 권고

1. F006의 제출 runtime과 direct Generation 동작을 기준선으로 고정한다.
2. 실제 Trial 완주를 훼손할 수 있는 timeout·동시성 변경을 품질 변경과 섞지 않는다.
3. Retriever는 별도 계층 평가에서 OFF·현재 gate·도메인 tool shortlist를 비교한다.
4. RAG가 성공 evidence를 한 건도 만들지 못하면 citation self-check를 행동 변경으로
   승격하지 않는다.
5. global health와 context seeking은 로컬 절대점수가 낮으므로 direct prompt의 다음
   품질 실험 후보로 둔다.
6. 공식 전체 시간이 36분 36초였으므로 점수를 유지하면서 RAG 입력과 tool schema를
   줄이는 방향으로 처리 시간을 개선한다.

F006의 의의는 새로운 citation 알고리즘의 효과가 아니라, **F005 계열의 안정적인
direct 중심 구조가 실제 Trial에서도 완주하며 기존 공식 최고점을 갱신했다는 것**이다.

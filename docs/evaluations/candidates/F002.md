# F002 프론티어 후보 평가 피드백

## 판정

**승격하지 않는다.** F002는 B002와 동일한 32개 manifest에서 46.88점, 평가 본체
517.70초(8분 38초)로 B002보다 훨씬 빨랐지만 3개 요청이 HTTP 502로 실패했다.
`coverage-v2`의 필수 조건인 32/32 완주를 충족하지 못했으므로 점수와 속도만으로
승격할 수 없다.

F002는 F001의 runtime 값을 바꾸지 않고 환경변수 override를 막은 소유권 리팩터다.
따라서 품질 개선을 기대하는 후보가 아니라 같은 동작을 재현 가능하게 고정하는 후보였다.
16개에서 보이지 않던 실패가 32개에서 드러났다는 점이 이번 평가의 가장 중요한 성과다.

## F003 권고

F003에서는 evidence 수를 늘리는 품질 실험보다 먼저 runtime 안정성을 단일 변수로 다룬다.

1. 의미 로직과 role tagging은 F002 그대로 유지한다.
2. upstream 동시성을 2에서 최소 4로 올리고, queue wait를 반드시 기록한다.
3. 요청 제한은 90초, upstream은 30초 부근의 D5 성공 기준을 우선 검토한다.
4. `coverage-v2` 생성 동시성 4에서 32/32, 420초 내 완주를 요구한다.
5. 안정성 확보 뒤 F004에서 `MAX_SELECTED_EVIDENCE` 변경을 별도 실험한다.

실제 Trial은 **20분 이내를 운영 목표**, **30분을 절대 상한**으로 둔다. F002의
로컬 속도는 목표에 부합할 가능성이 있지만 실패율 9.38%가 남아 있으므로 아직 Trial을
소비할 후보는 아니다.

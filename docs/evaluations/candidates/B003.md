# B003 벤치마크 후보 평가 피드백

## 판정

**폐기한다.** B003은 D5의 짧은 timeout과 높은 동시성을 복원해 B002의 긴 실행을
줄였지만, 정상 재실행에서도 19/32만 성공하고 420초 wall-clock 제한을 소진했다.
12건이 HTTP 502, 마지막 1건이 `run_timeout`이었다. 점수 30.14는 실패를 0점으로
포함한 유효한 결과지만, 완주율 59.38%인 후보의 품질 비교에는 의미가 제한적이다.

더 중요한 문제는 B003이 문서상 “runtime 정책만 변경”한 실험이 아니었다는 점이다.
B002가 `httpx2` 동시 cold start를 직렬화하던 `_post_with_cold_start_guard`를 제거했다.
첫 실행에서 컨테이너가 시작 직후 종료되고 32개 전부 `RemoteProtocolError`가 된 현상은
이 제거와 강하게 부합한다. 따라서 이번 결과를 timeout·동시성 값만의 효과로 해석하면
안 된다.

## 변경과 실험 오염

| 항목 | B002 | B003 |
|---|---:|---:|
| 요청 제한 | 170초 | 90초 |
| upstream 제한 | 75초 | 30초 |
| retrieval 제한 | 65초 | 40초 |
| upstream 동시성 | 2 | 6 |
| cold-start guard | 유지 | **제거** |

의도는 D5의 처리량 profile을 복원하는 것이었지만, transport 안전장치 제거와 MCP
lifecycle 변경이 함께 들어갔다. 특히 동시성 6으로 올리면서 cold-start 직렬화를
동시에 없앤 조합은 첫 연결 경쟁을 확대할 수 있다. B004는 이 변경을 그대로 이어받지
말아야 한다.

## 재현 기록

첫 실행은 4.03초 안에 32/32가 모두 `RemoteProtocolError: Server disconnected
without sending a response`로 실패했고 후보 컨테이너가 사라졌다. 동일 SHA 재실행은
일부 요청을 처리했으므로 공유 결과는 두 번째 실행을 사용한다. 동일 이미지가 시작
순서에 따라 전부 실패하거나 부분 성공하는 것은 그 자체로 승격 거부 사유다.

## 재실행 결과

| 지표 | 값 |
|---|---:|
| 로컬 프록시 점수 | **30.14** |
| bootstrap 95% 신뢰구간 | 17.70–43.11 |
| 성공 / 실패 | **19 / 13** |
| 성공률 | **59.38%** |
| HTTP 502 / run timeout | 12 / 1건 |
| 평균 모델 지연 | 42.21초 |
| p50 / p95 / 최대 지연 | 51.20초 / 64.60초 / 65.34초 |
| 평가 본체 시간 | **420.08초** |
| 성공 처리량 | 2.71건/분 |
| 승격 가능 | **아니요** |

성공 요청의 최대 지연이 65.34초로 제한된 것은 짧은 timeout의 결과지만, 빠르게
실패한 요청을 제외한 분포라서 안정성 개선으로 볼 수 없다. B002보다 전체 시간은
줄었으나 성공 수가 28개에서 19개로 감소했다.

## B002 비교

| 지표 | B002 | B003 | 변화 |
|---|---:|---:|---:|
| 점수 | 46.43 | 30.14 | -16.29 |
| 성공 | 28/32 | 19/32 | -9건 |
| 평균 모델 지연 | 57.14초 | 42.21초 | -14.93초* |
| 평가 본체 시간 | 1,047.75초 | 420.08초 | -627.67초 |

`*` 실패가 크게 늘어난 상태의 성공 요청 평균이므로 동일한 처리 성능 비교가 아니다.

## 다음 권고

1. B002의 cold-start guard를 반드시 복원한다.
2. transport/lifecycle 변경과 timeout·동시성 변경을 한 버전에 섞지 않는다.
3. 의미 로직을 고정하고 upstream 동시성 4부터 독립적으로 재시험한다.
4. 요청 90초·upstream 30초를 쓰더라도 502를 즉시 0점으로 끝내지 말고, 전체 deadline
   안에서 한 번의 제한된 재시도가 실제 작동하는지 telemetry로 확인한다.
5. 후보 stdout 수집 실패를 먼저 고쳐 phase·queue·MCP 지연이 결과 JSON에 병합되게 한다.

B003 SHA는 기준선이나 다음 후보의 부모로 사용하지 않는다.

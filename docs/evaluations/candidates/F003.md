# F003 프론티어 후보 평가 피드백

## 판정

**폐기한다.** F003은 D5의 요청·upstream timeout과 동시성 6을 적용했지만 11/32만
성공했다. HTTP 502가 20건, 504가 1건이며 성공률은 34.38%다. 316.30초 안에 모든
문항이 종료되어 wall-clock timeout은 피했지만, 이는 처리량 개선이 아니라 빠른 실패가
늘어난 결과다.

F002의 29/32보다 성공 수가 18개 감소했으므로 “동시성 2의 queue 적체가 502의 주원인”
이라는 가설은 이번 로컬 조건에서 지지되지 않는다. 다만 시작 후 46초 동안 B003과
동시에 실행되어 같은 Lunit backend에 부하를 더한 교란이 있으므로, 동시성 6 자체의
정확한 실패율을 확정하려면 단독 재실행이 필요하다. 어느 경우에도 현재 결과로는 승격할
수 없다.

## 가설 판정

- 동시성 6은 queue를 줄여도 upstream 순간 부하와 30초 timeout 실패를 크게 늘릴 수 있다.
- D5의 실제 Trial 성공 profile이 현재 F 계보와 로컬 동시성 4 조건에 그대로 이전된다는
  전제는 성립하지 않았다.
- B003와의 겹침 때문에 공유 backend 포화 가능성은 남지만, F003의 승격 실패 판정은
  바뀌지 않는다.
- role tagging의 품질 가설은 이번에도 runtime 실패에 가려져 평가되지 못했다.

# B009 로컬 평가 대기

## 핵심 가설

B008의 외부 근거 기반 Retrieval gate와 나머지 runtime을 유지하면서 L2 upstream
attempt 제한만 50초에서 30초로 줄이면, 느린 호출의 slot 점유를 제한해 전체 처리량을
높이고 420초 안의 완주 여유를 확보할 수 있다.

## 버전 식별자

- 트랙: 벤치마크상
- 버전: `B009`
- 브랜치: `yh-submission`
- SHA: 커밋 후 확정
- 리더보드 제출: 수행하지 않음
- 평가 상태: 현장 단독 평가 대기

## 변경 범위

| 항목 | B008 | B009 |
|---|---:|---:|
| L2 upstream attempt 제한 | 50초 | **30초** |
| 전체 요청 제한 | 120초 | 120초 |
| Retrieval 제한 | 40초 | 40초 |
| final 예약 | 50초 | 50초 |
| upstream 동시성 | 5 | 5 |
| Retrieval gate·prompt | 유지 | 유지 |

prompt, routing keyword, retry 횟수, MCP·context·evidence 상한과 cold-start 보호는
변경하지 않는다. 따라서 B008과의 차이는 L2 개별 attempt 제한 하나다.

## 예상 개선과 위험

- 예상 개선: 느린 initial/final L2 호출의 점유 시간 감소, 전체 처리량과 deadline
  headroom 증가.
- 예상 위험: 정상적으로 30초를 넘겨 완성되는 응답을 502로 전환해 성공률과 답변
  completeness를 떨어뜨릴 수 있다.
- 해석 경계: B004에서 30초 제한은 502 증가와 함께 관측됐으므로, 완주 시간이 줄어도
  inference 실패가 늘면 개선으로 판정하지 않는다.

## 현장 평가 기준

다른 후보와 동시에 실행하지 않고 `.\proxy yh-submission`으로 평가한다. B008과 같은
manifest에서 성공률, HTTP 502, initial/final attempt p95, 전체 시간과 성공 처리량을
비교한다. 32/32가 아니면 점수와 관계없이 Trial 후보로 승격하지 않는다.

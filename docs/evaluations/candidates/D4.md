# D4 평가 피드백

## 버전 정의

D4는 `dy-submission`의 커밋
`ec0d4a4a93d5a05606c8246514e831367e8812ca` 모델이다.

- 결과: `eval/results/D4-representative-conquer_val-16-20260821-122053.json`
- 로컬 프록시 점수: **27.79점**
- bootstrap 95% 신뢰구간: **11.56~45.28점**
- 성공: **12/16 (75%)**
- inference 실패: **4**
- judge 실패: **0**
- 리더보드 제출: 수행하지 않음

이번 평가는 `conquer_val`, representative 16개, seed 0, 반복 1회,
생성 동시성 2 조건으로 수행했다. 샘플 manifest SHA-256은
`5aaba42ae20d13b8b65cef0a449b9a69b756525c8ae9d7e373c1e077188eb045`이다.

## 결과 해석 시 주의점

현재 채점 로직은 추론 실패를 0점으로 포함한다. 성공한 12개만의 평균은
**37.05점**이지만, 실패를 포함한 공식 로컬 프록시 점수는 **27.79점**이다.

실패 4건의 원인은 모델 서버 프로세스 종료가 아니었다. 컨테이너는 평가가
끝날 때까지 정상 동작했으며, 상위 Lunit 모델 API에서 다음 오류가 발생했다.

- 최종 생성 단계 `ReadTimeout`: 1건
- 상위 모델 API의 연속 `502 Bad Gateway`: 3건

따라서 27.79점은 이번 실행에서 관측된 가용성까지 포함한 결과로는 유효하지만,
D4의 순수 응답 품질만을 안정적으로 대표한다고 보기는 어렵다. 특히 95% 신뢰구간이
넓고 실패가 특정 시간대에 몰려 있으므로, 후보 확정 전에는 동일 manifest로 재평가해
일시적인 상위 API 장애와 재현 가능한 모델 문제를 분리해야 한다.

## 실행 안정성 확인

최초 시도에서는 이전 평가 컨테이너가 백그라운드에 남은 상태에서 새 평가가
겹쳐 모델 서버가 `exit 139`로 종료됐다. 남은 평가를 종료하고 모델 컨테이너를
재기동한 뒤 수행한 동시성 2 smoke test는 2/2 성공했다. 본 평가에서도 서버
크래시는 재발하지 않았다.

평가를 다시 실행할 때는 다음 순서를 지킨다.

1. 실행 중인 evaluator 컨테이너가 없는지 확인한다.
2. 후보 모델 컨테이너를 새로 시작하고 `/v1/models` 200을 확인한다.
3. 동시성 2 smoke test를 통과시킨다.
4. representative 16개 본 평가를 하나만 실행한다.

## D1·D3와의 비교 제한

D1과 D3의 대표 평가는 32개 샘플로 수행됐고 D4는 16개 샘플이다. manifest가
다르므로 문항별 승패나 점수 차이를 직접 비교하면 안 된다. 공정한 후보 비교가
필요하면 D1과 D3도 D4와 동일한 representative 16개 manifest로 다시 실행한다.

## 판정

D4의 이번 실행은 **가용성 포함 27.79점, 성공률 75%**다. 실패를 제외한 응답도
instruction following과 context awareness가 약해 현재 결과만으로 D3보다 낫다고
판정할 근거는 없다. 동일 16개 manifest 재평가에서 16/16 성공 여부를 먼저 확인한
뒤 품질 비교를 진행하는 것이 적절하다.

## 동일 manifest 재평가

상위 API의 일시 장애 여부를 확인하기 위해 같은 SHA와 같은 manifest로 한 차례
재평가했다.

- 결과: `eval/results/D4-representative-rerun-conquer_val-16-20260821-123153.json`
- 로컬 프록시 점수: **28.27점**
- bootstrap 95% 신뢰구간: **9.15~48.81점**
- 성공: **10/16 (62.5%)**
- inference 실패: **6**
- 성공한 10개만의 평균: **45.23점**
- 전체 평가 시간: **418.68초**

원 실행과 재평가의 manifest SHA-256은 모두
`5aaba42ae20d13b8b65cef0a449b9a69b756525c8ae9d7e373c1e077188eb045`로
동일하다. 재평가 후반에는 Lunit 모델 API와 MCP API가 같은 시각에 연속 502를
반환했다. D4 컨테이너는 종료되지 않았다.

| 실행 | 점수 | 성공 | 실패 제외 평균 |
|---|---:|---:|---:|
| 최초 평가 | 27.79 | 12/16 | 37.05 |
| 동일 manifest 재평가 | 28.27 | 10/16 | 45.23 |

두 실행의 가용성 포함 점수는 약 28점으로 비슷하지만, 성공 문항 구성과 실패 제외
평균은 크게 달라졌다. 현재 Lunit 상위 서비스의 간헐적 502가 결과를 지배하고 있어
D4의 안정적인 품질 점수는 아직 확정할 수 없다. 추가 재평가는 서비스 상태가 안정된
시간대에 수행하고, 16/16 성공 결과만 후보 간 품질 비교에 사용하는 것이 적절하다.

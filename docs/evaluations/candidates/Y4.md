# Y4 개발 피드백 — 평가 대기

## 버전 정의

Y4는 `yh-submission2`의 런타임 커밋
`44141fd93ba9f593c4cc63e54c97a9195b3a9210`이다. Y3의 response guidance를
유지한 채 비용이 큰 경로를 줄이는 지연 최적화 후보다.

- 기반: Y3 `e59ec07`
- 개발 브랜치: `yh-submission2`
- 로컬 단위·회귀 테스트: 65/65 성공
- scored proxy: 미실행
- 판정: 평가 대기

Y3가 Y2보다 10.38점 하락했다는 현장 결과는 Y4 구현 이후 확인됐다. 따라서 Y4는
단순히 Y3보다 빠른지만 볼 수 없고, Y3에서 무너진 instruction following과
communication이 회복되는지도 Y2 기준으로 비교해야 한다.

## 변경 묶음

### Retrieval 입구 제한

가이드라인, 근거·출처, 최신 정보, 약물 용량·금기·상호작용·허가·안전성,
보험·급여·법률 keyword가 있을 때만 retrieval tool을 제공한다. 일반 증상 설명,
생활 관리와 공감 질문은 L2 한 번으로 끝내는 것이 목적이다.

### Citation 재생성 제거

존재하지 않는 citation은 결정론적으로 제거한다. citation 누락이 있더라도 별도의
L2 repair 호출을 하지 않는다. 지연은 줄지만 citation completeness가 낮아질 수 있다.

## 사전 진단

이 후보는 routing gate, timeout, context budget, MCP budget, citation repair를 한 번에
바꿨다. 결과가 좋아도 어느 변경이 기여했는지 바로 분리할 수 없다. 또한 retrieval에
진입한 요청에는 여전히 21개 MCP tool schema가 전달되므로 Y2/Y3에서 관측한 핵심
입력 병목을 직접 제거한 구현은 아니다.

Y4 평가에서는 다음을 별도로 측정한다.

1. direct/RAG 경로 수와 routing false negative
2. Retrieval 40초 timeout 횟수
3. `partial`·`no_evidence` 비율
4. unknown citation 삭제와 missing citation 횟수
5. instruction following·communication의 Y2 대비 회귀
6. 평균뿐 아니라 RAG 요청의 긴 꼬리 지연

## 승격 기준

1. Y2·Y3와 같은 representative 16개 manifest를 사용한다.
2. 16/16 성공을 유지한다.
3. Y2 54.68점에서 3점 넘게 하락하지 않는다.
4. 평균 모델 지연 45초 이하를 1차 목표로 한다.
5. instruction following과 accuracy에서 대형 회귀가 없어야 한다.
6. 근거 필요 표본에서 retrieval 누락과 citation completeness 하락이 없어야 한다.

## 판정 원칙

Y4가 기준을 충족하더라도 후속 ablation에서 routing, budget, repair 제거의 기여도를
분리한다. 실패하면 Y3를 유지하지 않고 **Y2로 돌아가 계측만 추가한 후보부터** 다시
시작한다.
